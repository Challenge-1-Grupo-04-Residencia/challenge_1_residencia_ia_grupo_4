    Legenda

    • Canal: Site · Extensão · Celular · API
    • MoSCoW (proposta do PO): M Must · S Should · C Could · W Won't (agora). A proposta é revisada na priorização (ver Planning Poker)

    Convenções desta tabela

    Todo requisito diz o que o sistema faz, com o sujeito padronizado em "O sistema deve". Como cada função é implementada (bibliotecas, APIs e modelos) fica em Como a Vera funciona e em Hipóteses técnicas, para que uma troca de técnica não invalide o requisito. Qualidades como desempenho, acessibilidade, responsividade e identidade visual são requisitos não funcionais.

    Chat e conversa¶

    ID Requisito Canal MoSCoW
    RF-01 O sistema deve receber um link, texto ou afirmação enviados pelo usuário para checagem M
    RF-02 O sistema deve responder em formato de chat, em linguagem simples M
    RF-03 O sistema deve exibir o andamento da investigação, indicando a etapa em execução M
    RF-04 O sistema deve aceitar perguntas de acompanhamento sobre um resultado já entregue S
    RF-05 O sistema deve apresentar a reação da Vera correspondente à faixa de veracidade do resultado S

    Motor de veracidade¶

    ID Requisito Canal MoSCoW
    RF-06 O sistema deve extrair título, texto, autor e data de publicação a partir de uma URL M
    RF-07 O sistema deve executar a checagem em camadas (N0 a N4), da mais barata para a mais cara M
    RF-08 O sistema deve encerrar a checagem assim que a regra de parada for atingida M
    RF-09 O sistema deve calcular o score de veracidade e a confiança do resultado M
    RF-10 O sistema deve aplicar as regras que se sobrepõem ao score (RN-01 a RN-04) M
    RF-11 O sistema deve reaproveitar checagens anteriores dentro do prazo de validade (RN-09) S
    RF-12 O sistema deve concluir a checagem em modo econômico, sem a camada de LLM S
    RF-13 O sistema deve registrar a dificuldade da checagem, pela camada em que ela parou C

    Reputação de fontes¶

    ID Requisito Canal MoSCoW
    RF-14 O sistema deve consultar a confiabilidade do veículo que publicou a notícia M
    RF-15 O sistema deve permitir manter e atualizar a base curada de veículos M
    RF-16 O sistema deve consultar a idade do domínio M
    RF-17 O sistema deve consultar checagens já publicadas por agências sobre a mesma alegação M
    RF-18 O sistema deve manter o histórico de notícias falsas confirmadas por domínio (RN-10) S
    RF-19 O sistema deve identificar domínios que imitam veículos conhecidos (RN-02) C
    RF-20 O sistema deve expor a reputação de veículos por uma API pública C

    Análise de conteúdo¶

    ID Requisito Canal MoSCoW
    RF-21 O sistema deve classificar a probabilidade de falsidade a partir do estilo de escrita M
    RF-22 O sistema deve medir o grau de sensacionalismo do texto M
    RF-23 O sistema deve medir a intensidade emocional do texto M
    RF-24 O sistema deve verificar se o texto cita fontes verificáveis S
    RF-25 O sistema deve estimar se o texto foi gerado por IA W
    RF-26 O sistema deve identificar opinião e sátira (RN-03) C

    Corroboração¶

    ID Requisito Canal MoSCoW
    RF-27 O sistema deve buscar notícias semelhantes publicadas por outros veículos M
    RF-28 O sistema deve contar quantos veículos confiáveis publicaram o mesmo fato M
    RF-29 O sistema deve extrair do texto as alegações checáveis M
    RF-30 O sistema deve verificar se cada evidência sustenta, contradiz ou é neutra em relação à alegação S
    RF-31 O sistema deve detectar cópia com alteração de outra fonte C

    ID Requisito Canal MoSCoW

    RF-33 O sistema deve permitir consultar o detalhamento de cada sinal e do seu peso S
    RF-34 O sistema deve oferecer dicas de pensamento crítico ligadas aos sinais encontrados S
    RF-35 O sistema deve permitir que o usuário conteste um resultado C
